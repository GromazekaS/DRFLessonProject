# DRFProject

Автоматизированный деплой Django-приложения с использованием Docker, Docker Compose и GitHub Actions.

**Ссылка на рабочее приложение:** http://158.160.129.211/api/courses

---

## 🐳 Контейнеризация

Проект разбит на микросервисы, каждый в отдельном контейнере:

- **Django** + **Gunicorn** — `web`
- **PostgreSQL** — `db`
- **Redis** — `redis`
- **Celery** — `celery_worker`, `celery_beat`
- **Nginx** — `nginx`

Управление осуществляется через **Docker Compose**. Для сервиса `web` написан `Dockerfile`, для `nginx` — собственный `Dockerfile` в папке `nginx/`. Остальные образы — официальные.

---

## ⚙️ CI/CD (GitHub Actions)

При каждом пуше в репозиторий запускается **GitHub Actions workflow**, который выполняет:

1. **Линтинг** — `flake8`
2. **Тесты** — `python manage.py test`
3. **Сборка и публикация Docker‑образа** — образ `web` пушится в Docker Hub с тегом `{{ sha }}`
4. **Деплой на сервер** — через SSH:
   - Копируются `docker-compose.yml` и конфиги `nginx`
   - Генерируется `.env` из секретов GitHub
   - Скачивается свежий образ
   - Запускается `docker-compose up -d` с автоматическим применением миграций

Все секреты (`DOCKER_HUB_*`, `SSH_*`, `DJANGO_SECRET_KEY`, `DB_PASSWORD`) хранятся в Secrets репозитория.

---

## 🚀 Деплой на удалённый сервер

Деплой полностью автоматизирован через GitHub Actions. При успешном прохождении тестов и сборки на сервере **автоматически**:

- Останавливаются старые контейнеры
- Подтягивается актуальный образ `web`
- Запускается полный стек через `docker-compose up -d`
- Выполняются миграции, сбор статики

Обновление приложения происходит без ручного вмешательства.
